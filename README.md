# CryptoPulse - 虚拟货币实时分析系统

一个基于纯前端技术的加密货币实时分析系统，集成技术指标分析、新闻情感分析、智能交易信号生成等功能。支持移动端自适应，数据来自币安（Binance）公开 API 与 CoinGecko，无需后端服务即可运行。除加密货币外，也覆盖**币安美股标的**（USDT-M 合约的 TradFi 板块）。

## 📡 数据来源与覆盖范围

三个数据源按标的自动路由，各自的能力边界与限制都在界面上如实标注：

| 数据源 | 覆盖 | 价格/K线 | 备注 |
|--------|------|----------|------|
| 币安现货 | 现货 USDT 交易对 | 24h 行情、多周期K线 | 默认数据源 |
| 币安 USDT-M 合约 | **美股标的**、衍生品 | 24h 行情、多周期K线、资金费率、持仓量 | 识别依据是 `underlyingType` 字段，不是硬编码名单 |
| CoinGecko | 币安未收录的币种（如 GWEI） | 价格/市值；K线粒度由天数决定、成交量需近似 | 无 key 模式；缺失的因子不参与评分 |

### 关于美股（实测结论）

币安美股有**两个市场**，本应用只把合约标的放进「美股」分类：

- **USDT-M 合约**（`AAPLUSDT` 等，162 个标的）：日线 166 根、周线 24 根，24h 成交额约 5408 万美元
- **现货代币化股票**（`AAPLB` 等，代码为原代码 + B）：日线 52 根、周线 8 根，24h 成交额约 203 万美元

合约的历史深度是现货的 3 倍、流动性约 26 倍，所以分析统一用合约标的。现货那批在搜索结果里仍可见并标注「代币」——它们的代码与普通币种无法靠字段区分，是用「合约美股名单 + B 后缀」反查配对识别出来的（不能简单「以 B 结尾」，否则 BNB/SHIB/ARB 会被误伤）。

美股的两点限制必须知道：

1. **历史深度浅，且补充不了**：合约 2026-04-06 才上线，日线约 166 根、周线约 24 根。带 `startTime` 往前回溯同样停在 2026-04-06，换 `indexPriceKlines` / `markPriceKlines` 也只有 170 根 —— 这是**标的年龄**的限制，不是取数方式的问题：标的只存在了 166 天，就不可能有 200 天的成交记录。所以 MA200 取不到不是"数据缺失"，而是这个窗口在数学上不可得。处理方式见下方「长期均线（大趋势线）」。
2. **只有两项因子**：加密恐慌贪婪指数与加密新闻对个股不适用，合约资金费率实测长期贴近 0（远低于 `calculateDerivativesScore` 的 0.05% 阈值，恒为 50 分），三者都不参与评分。所以美股的综合评分只由技术面 + 量能按 2:1 归一构成，卡片上会标「· 2因子」，因子面板对不适用的项显示「—」而不是 50 分。

## ✨ 功能特性

### 核心功能
- **实时价格监控** - 支持多种主流加密货币实时价格追踪
- **K线图表** - 交互式K线图，支持多时间周期切换（1H/1D/1W/30D）
- **技术指标** - MA7/MA25均线、RSI、MACD、布林带等常用指标
- **支撑压力位** - 自动计算关键支撑位和压力位
- **高低点标记** - 自动识别并标记近期高低点
- **美股标的** - 币安合约里的美股（含 ETF、杠杆/反向 ETF），共 162 个

### 智能分析
- **综合信号系统** - 结合技术面和消息面生成买入/卖出/观望信号
- **新闻情感分析** - 自动获取加密货币新闻，进行情感倾向分析
- **操作建议** - 智能生成加仓/减仓/观望等操作建议
- **评分系统** - 技术面评分、消息面评分、综合评分（0-100分）

### 用户体验
- **自选币种** - 支持添加/删除自选币种，最多10个
- **一键切换** - 快速切换不同币种查看分析
- **移动端适配** - 完美适配手机、平板、桌面端
- **自动刷新** - 数据自动更新，无需手动刷新
- **本地存储** - 自选列表保存在本地，下次访问自动恢复

## 🚀 快速开始

### 方式一：直接打开
1. 下载项目文件到本地
2. 双击 `index.html` 即可在浏览器中打开
3. 无需安装任何依赖

### 方式二：本地服务器（推荐）
```bash
# 使用 Python
python3 -m http.server 8080

# 或使用 Node.js
npx serve .

# 或使用 VS Code Live Server 插件
```
然后访问 `http://localhost:8080`

### 方式二（局域网手机/其他电脑访问）

在运行项目的电脑上执行：

```bash
# 终端 1：启动模拟盘、登录和用户数据服务，绑定局域网网卡
HOST=0.0.0.0 node server/store.js

# 终端 2：启动网页服务器，绑定局域网网卡
python3 -m http.server 8080 --bind 0.0.0.0
```

查询这台电脑的局域网 IP（例如 `192.168.1.23`），然后在手机或其他电脑打开：
`http://192.168.1.23:8080`。页面会自动把登录和模拟盘请求发到同一台电脑的 `8788` 端口，不要在其他设备上填写 `127.0.0.1`。

如果打不开，检查电脑防火墙是否允许 TCP `8080` 和 `8788`，并确认两台设备连接的是同一个局域网。这个模式适合家庭或办公室内使用；需要从互联网访问时，应使用 Cloudflare Tunnel、Tailscale 等带访问控制的方式，不要直接把 `8080/8788` 映射到公网。

### 方式三：部署到静态网站
可直接部署到 Vercel、Netlify、GitHub Pages 等静态网站托管服务。

### 方式四：把模拟盘记录到本地后端（可选）

模拟盘（交易页 → 模拟盘）默认只存在浏览器的 `localStorage` 里：清一次缓存、换个浏览器、
换台设备，总资金、配额、持仓与成交记录就都没了。下面这个本地服务把它们落到磁盘：

```bash
node server/store.js
# → 监听 http://127.0.0.1:8788
```

然后在应用里打开「交易 → 模拟盘 → 记录到后端」，地址填 `http://127.0.0.1:8788` 并保存。
保存时会自动连一次：绿色角标表示已连通，也可以随时点「立即同步」手动推一次。

首次打开页面时注册或登录即可。服务端会在 `server/data/paper-state.json` 中保存用户、会话和模拟盘数据；密码只保存为 scrypt 哈希，会话只保存令牌的 SHA-256 摘要。**会话随数据一起落盘，所以重启服务不会被登出**（自登录起 30 天过期）。当前登录接口适合本机开发和自用，后续可继续接入验证码、微信登录和限流。

**这不是必需服务。** 不启动它模拟盘照常使用，但用户登录和跨设备同步需要启动该服务。
数据落在 `server/data/paper-state.json`（已在 `.gitignore` 中，是你的真实记录，不会入库）。

几点设计取舍：

- **浏览器里那份仍是权威副本。** 后端只是镜像，写入有 2 秒防抖，所以后端读到的可能比本机稍晚。
- **冲突按时间戳取新**：两边都有数据时，谁的时间戳更晚用谁的，不做字段级合并。
  模拟盘只有一台设备在写，这个策略够用且可解释。
- **它只监听 `127.0.0.1`**，登录后的模拟盘数据按用户名隔离。若要暴露到网络，必须先补 HTTPS、限流和更强的登录验证。
- 它与 `server/proxy.js`（币安签名代理）是**两个独立进程**：签名代理的端点白名单收得很紧
  （只有账户查询与下单撤单），往里加文件读写路由会破坏那个前提；
  而且持久化模拟盘并不需要密钥，不该因此逼你去配币安 API Key。

## 📱 小程序版（个人主体也能用）

`miniprogram/` 是一份**原生微信小程序**，用微信开发者工具导入后在手机上预览即可自己使用，
不需要域名、不需要服务器、**也不需要 ICP 备案**（预览版不受备案限制）。

之所以不是「套一层 web-view」：微信**不允许个人主体小程序配置业务域名**，而 `web-view` 依赖业务域名，
个人主体用不了。所以界面用 WXML/WXSS 重写、K线用 Canvas 手绘，但**分析逻辑一行都没重写** ——
`libs/` 下的指标、信号、美股数据源是从 `js/` 同步过来的同一份代码。

```bash
# 改动了 js/technical.js、js/signals.js、js/stocks.js 中的任何一个后，同步一次
node miniprogram/sync-libs.js
```

详细的导入步骤、手机上打不开数据的处理、以及本版与网页版的功能差异，见
[`miniprogram/README.md`](miniprogram/README.md)。

## 📊 技术指标说明

### RSI (相对强弱指数)
- **周期**: 14
- **超买**: >70（可能回调）
- **超卖**: <30（可能反弹）
- **中性**: 30-70

### MACD (指数平滑异同移动平均线)
- **快线**: 12日EMA
- **慢线**: 26日EMA
- **信号线**: 9日EMA
- **金叉**: MACD上穿信号线（看涨）
- **死叉**: MACD下穿信号线（看跌）

### 长期均线（大趋势线）
名义窗口是 **MA200**，用于判断大趋势（价格在均线上方 +3 分，下方 -3 分）。

标的可能比 200 根K线还年轻（币安美股合约日线约 166 根、周线约 24 根，且如前所述补不了），
此时按 `TechnicalAnalysis.LONG_MA_LADDER` 从长到短（**200 → 150 → 120 → 99 → 60**）
挑出**可用根数撐得住的最长窗口**，用这个窗口做判断，并同时做到三件事：

- 指标卡片的标题直接写成实际窗口（如「MA150 牛熊线」），卡片下方注明「166 根K线不足 200，MA200 不可得，此处改用 MA150」；
- 技术面信号文案里带上实际窗口与原因（如「价格站在MA150上方，大趋势偏多（历史深度不足 MA200，改用 MA150）」），不会出现「MA200」字样冒充；
- `breakdown.longMA` 记录 `{ window, substituted, value }`；连最短的 60 都撐不住时（美股周线 24 根）记为 `window: null`，明确表示**这一项没参与评分**，而不是让它静默消失、分数看起来照样完整。

加密币的历史足够长，不受影响：BTC 日线 200 根即走 MA200 原逻辑（`breakdown.longMA.window === 200`、`substituted === false`）。
降级窗口与 MA200 不是同一口径，两者之间的大趋势结论不宜直接横向比较。

### 均线 (MA)
- **MA7**: 7日简单移动平均线（短期趋势）
- **MA25**: 25日简单移动平均线（中期趋势）
- **多头排列**: 价格 > MA7 > MA25（看涨）
- **空头排列**: 价格 < MA7 < MA25（看跌）

### 布林带
- **中轨**: 20日SMA
- **上轨**: 中轨 + 2倍标准差
- **下轨**: 中轨 - 2倍标准差
- **触及上轨**: 可能遇压回调
- **触及下轨**: 可能获得支撑反弹

## 🎯 信号解读

### 综合评分
| 分数 | 信号 | 仓位提示 |
|------|------|----------|
| 70-100 | 强烈买入 | 分批建仓，仓位控制在 60-80% |
| 58-69 | 买入 | 轻仓试探，逢回调加仓，仓位 30-50% |
| 43-57 | 观望 | 不给仓位建议，提示「等待更明确的信号」 |
| 31-42 | 卖出 | 降低仓位至 30% 以下 |
| 0-30 | 强烈卖出 | 减仓至 20% 以下，或离场观望 |

上表为均衡档（默认）。阈值随「信号灵敏度」档位收紧或放宽，区间边界也跟着移动：保守档
74 / 63 / 37 / 26，灵敏档 66 / 54 / 46 / 34（依次为强烈买入、买入、卖出、强烈卖出；前两项
用 ≥，后两项用 ≤）。K线买卖点与实时信号共用同一档位的阈值，两处的分档判定一致；但档位里的
子因子权重与最小落点间隔只作用于买卖点一侧（以及模拟盘与回测统计），实时综合评分走的是
固定分值，见下方「技术面因子」。

仓位提示按已经算出的信号标签分流，因此在任何档位下都与上面的信号标签一致。

加权构成：

- **加密货币**：技术面 40% + 量能 20% + 市场情绪 16% + 消息面 12% + 衍生品 12%
- **美股**：技术面 40% + 量能 20%（按 2:1 重新归一）；其余三项对个股不适用，详见上方「关于美股」

因子取值口径不同的标的之间，评分不可直接横向比较，界面上会标出「· 2因子」以作区分。

各项因子具体怎么算、取不到数据时怎么处理、各档位的阈值是多少，见下方「算法说明」。

### 支撑压力位
- **强压力位**: 第二压力位，到达可考虑大幅减仓
- **压力位**: 第一压力位，到达可部分止盈
- **支撑位**: 第一支撑位，到达可轻仓试探
- **强支撑位**: 第二支撑位，到达可考虑加仓

## 🧮 算法说明

从K线算到一个买卖结论分五步：

1. 由K线算出技术指标（`js/technical.js`）；
2. 五个因子各自得出 0~100 的分值：技术面、量能、市场情绪、消息面、衍生品；
3. 按权重加权求和，除以参与权重的总和，四舍五入得到综合分；
4. 综合分对照当前灵敏度档位的阈值，判定为强烈买入 / 买入 / 观望 / 卖出 / 强烈卖出（`js/signals.js`）；
5. 模拟盘成交前再过一道费率闸门（默认关闭）。

### 因子权重

| 因子 | 加密币 | 美股 | 取不到输入时 |
|------|-------|------|-------------|
| 技术面 | 40 | 40 | — |
| 量能 | 20 | 20 | K线不足 21 根时该因子返回 50 |
| 市场情绪 | 16 | 0 | 取不到恐慌贪婪指数时按 50 参与 |
| 消息面 | 12 | 0 | 剔除该因子，按剩余权重重算 |
| 衍生品 | 12 | 0 | 剔除该因子，按剩余权重重算 |

缺失的因子一律剔除后重新归一，而不是让它以常数 50 参与 —— 界面上这一格会显示「—」，
若分值里还带着一个 50，用户按展示出来的因子复现不出这个总分。剔除后权重之和会变，
每条预测记录都把当时的实际权重存了下来，所以历史分数可以逐笔还原。

### 技术面因子

技术面有两条评分路径，用途不同，调因子时要知道自己改的是哪一条。

**实时路径**（`calculateTechnicalScore`）只算当前这一根K线，结果进入界面显示的「综合评分」。
它在 50 分基础上按固定分值加减：

| 子因子 | 看多 | 看空 |
|--------|------|------|
| RSI(14) | <20 加 15；<30 加 12；<40 加 6 | >80 减 15；>70 减 12；>60 减 4 |
| MACD | 金叉加 10；柱由负转正加 5 | 死叉减 10；柱由正转负减 5 |
| 均线排列 | 价 > MA7 > MA25 加 7；价 > MA7 但 MA7 < MA25 加 3 | 价 < MA7 < MA25 减 7；价 < MA7 但 MA7 > MA25 减 2 |
| 长期均线 | 价格在窗口上方加 3 | 价格在窗口下方减 3 |
| 短期动量 | MA3 > MA7 加 6；ROC 超死区加 6 | MA3 < MA7 减 6；ROC 低于负死区减 6 |
| 布林带 | 触及下轨加 8 | 触及上轨减 8 |
| VWAP | 价格在 VWAP 上方加 5 | 下方减 5 |
| StochRSI | K、D 均 <20 加 10；K > D 且 K <50 加 5 | K、D 均 >80 减 10；K < D 且 K >50 减 5 |
| KDJ | K、D 均 <20 加 8；K > D 加 2；J <0 加 3 | K、D 均 >80 减 8；K < D 减 2；J >100 减 3 |
| AHR999 | 价格 ÷ MA200 < 0.45（深度价值区）加 7；< 1.2（核心积累区间）加 4 | ≥ 1.2（过热区）减 5 |
| OBV | 近 10 根 OBV 上行且价 > MA25 加 5 | OBV 下行且价 < MA25 减 5 |

加总后夹到 0~100。长期均线的窗口按可用根数从长到短降级（MA200 → 150 → 120 → 99 → 60），
实际用了哪个窗口会写在指标卡片与信号文案里，连最短窗口都撑不住时记为「未参与评分」。

长期均线这一项和上面的均线排列写在同一个 `if (ma7 && ma25 && currentPrice)` 里：MA7 或
MA25 缺失时它同样不会被判断，`breakdown.longMA` 连字段都不会写入 —— 不是「记了个 null」，
而是这一项压根没跑。

**序列路径**（`buildSignalSeries`）逐根重放整段K线，结果用于图上买卖点标注、模拟盘回放
与档位实测统计。它的子因子权重可由灵敏度档位调整：

| 子因子 | 含义 | 保守 | 均衡 | 灵敏 |
|--------|------|------|------|------|
| macdPos | MACD 在信号线上方还是下方 | 6 | 5 | 4 |
| macdHist | 柱体比上一根放大还是缩小 | 5 | 5 | 5 |
| maCross | MA7 与 MA25 的排列关系 | 6 | 4 | 3 |
| priceMa25 | 价格在 MA25 上方还是下方 | 5 | 3 | 2 |
| maFast | MA3 与 MA7 的交叉方向 | 4 | 7 | 9 |
| momentum | 3 周期动量是否超过死区 | 5 | 8 | 10 |
| kdj | K 与 D 的相对方向 | 6 | 6 | 7 |
| stoch | StochK 与 StochD 的相对方向 | 3 | 5 | 7 |
| boll | 是否触及布林上轨或下轨 | 5 | 4 | 3 |
| volume | 价涨量增或价跌量增 | 6 | 6 | 6 |
| rsiScale | RSI 超买超卖的缩放系数 | 0.9 | 0.8 | 0.7 |

其中 RSI 项按 RSI <30 加 10、<45 加 3、>70 减 10、>55 减 3，再乘 rsiScale；
3 周期动量的死区随波动自适应，逐根取当时算得出的尺度，不使用未来数据。

买卖点的落点规则：只在多空方向真正切换时才标一个点，同一方向内的强弱变化
（买入与强烈买入之间）不重复标注，两次落点间隔小于该档位最小间隔的翻转直接忽略。

### K线预热口径

MACD 是 EMA 递推，RSI 是 Wilder 平滑，KDJ 的 D 值从 50 起递推 —— 这三类指标的读数
取决于它前面有多少根K线，所以「只给 200 根」与「给全历史」算出的同一根K线并不相同。
三处用法的预热并不一样：

| 用途 | 指标怎么算 | 每根K线拿到的预热 |
|------|-----------|------------------|
| 线上应用（买卖点标注、模拟盘） | 对抓到的 200 根算一次（`getBinanceInterval` 的 `limit: 200`） | 第 i 根只有 i+1 根 |
| 回测的档位实测统计 | 对全历史算一次 | 实际数千根 |
| 回测的基准因子 | 逐根滑一个 200 根窗口重算 | 每根满 200 根 |

以 BTC 1 小时、窗口最后一根为例：

| 指标 | 200 根窗口 | 全历史 | 相对差 |
|------|-----------|--------|--------|
| MACD 线 | 139.5079 | 139.5076 | +0.00% |
| MACD 柱 | 23.2150 | 23.2151 | −0.00% |
| RSI(14) | 51.6072 | 51.6072 | −0.00% |
| KDJ 的 D | 70.3290 | 70.3290 | +0.00% |

差异随预热变短而放大：倒数第 100 根（预热 101 根）MACD 柱差 −0.65%；窗口第 11 根
（预热 11 根）KDJ 的 D 差 −20.1%，且 MACD、RSI、StochRSI 都还没算出来。

- 界面正在显示的当前根预热已满 200 根，与回测数字实质一致 —— 实测最近 20 根上，
  MACD 位置给出的多空方向与全历史口径完全一致（0/20 不同）。
- 图表最左端那几十根的标注是用更短的预热算出来的，与回测统计里同一时刻的数字不等价，
  不宜逐根对照，也不要拿它去核对档位实测的命中率。

还有一次可见的截断：简单均线 MA200 要求前面正好 200 根，所以在 200 根的窗口里只有
最后一根有值（实测 1/200 根有值，全历史下 26105/26304 根有值）。AHR999 与长期均线
趋势都取这个末位值，因此它们只对当前这一根成立，历史K线上没有读数。

### 量能因子

量比 = 最近一根已收盘K线的成交量 ÷ 20 周期均量。

| 判定 | 条件 | 加减分 |
|------|------|--------|
| 显著放量 | 量比 ≥ 2 | +12 |
| 温和放量 | 量比 ≥ 1.5 | +7 |
| 小幅缩量 | 量比 < 0.8 | −4 |
| 极度缩量 | 量比 < 0.5 | −8 |
| 量价齐升 | 5 根涨超 0.5% 且量比 ≥ 1.2 | +12 |
| 缩量上涨 | 5 根涨超 0.5% 且量比 < 0.8 | −10 |
| 放量下跌 | 5 根跌超 0.5% 且量比 ≥ 1.2 | −14 |
| 缩量回调 | 5 根跌超 0.5% 且量比 < 0.8 | +6 |
| 量能持续放大 | 近 5 周期均量 > 前 5 周期均量 × 1.15 | +6 |
| 量能持续萎缩 | 近 5 周期均量 < 前 5 周期均量 × 0.85 | −6 |

起点 50，加总后夹到 0~100。正在走的那根K线不参与计算；它的盘中量能只用来生成一条
文字提示（按已过去的时间比例折算量比），不改动分数。

### 市场情绪因子

恐慌贪婪指数反向使用：指数越低，因子分越高。

| 指数 | 因子分 |
|------|--------|
| < 20 | 75 |
| 20 ~ 39 | 65 |
| 40 ~ 49 | 55 |
| 50 ~ 59 | 45 |
| 60 ~ 79 | 35 |
| ≥ 80 | 25 |

### 衍生品因子

按当期资金费率对杠杆拥挤度打分，起点 50：

| 资金费率 | 加减分 |
|----------|--------|
| > 0.1% | −20 |
| 0.05% ~ 0.1% | −10 |
| −0.05% ~ 0 | +5 |
| < −0.05% | +15 |

费率偏高说明多头拥挤，扣分；为负说明空头付费给多头，加分。

### 消息面因子

每条新闻按情感分加权平均，越靠前的新闻权重越高（第 1 条权重 1，最后一条 0.5，线性递减）。
平均值 ≥60 记为正面，≤40 记为负面。没有任何新闻可取到时，该因子被剔除。

### 费率闸门

买卖点本身没有优势（实测命中率约 48%），所以模拟盘不默认让它独自决定开仓，另有一个
口径独立的闸门可选：

- 买入要求该K线的资金费率 90 天滚动分位 ≤ 33%，卖出要求 ≥ 67%；
- 分位只用该K线开盘之前已结算的费率计算，不使用未来信息；
- 拿不到分位（历史不足 30 期或接口失败）时一律拒绝开仓，宁可错过也不在信息缺失时下注。

实测（BTC/ETH，2023-09 ~ 2026-08，1 小时，已扣双边 20bp）：不过滤 1997 轮、胜率 28.1%、
单笔 −16.9bp；开启闸门 128 轮、胜率 51.1%、单笔 +18.3bp。这是把「必亏」拉回「大致打平」，
不是把它变成赚钱策略。研究结论只在 1 小时上成立，但代码里该闸门对所有周期生效 ——
4 小时与日线上可能出现信号成立却被拦下的情况，这一点尚未处理。

### 灵敏度档位

阈值同时用于实时信号与图上买卖点，两处口径一致。

| 档位 | 强烈买入 | 买入 | 卖出 | 强烈卖出 | 最小落点间隔 |
|------|---------|------|------|---------|-------------|
| 保守 | ≥ 74 | ≥ 63 | ≤ 37 | ≤ 26 | 6 根 |
| 均衡（默认） | ≥ 70 | ≥ 58 | ≤ 42 | ≤ 30 | 2 根 |
| 灵敏 | ≥ 66 | ≥ 54 | ≤ 46 | ≤ 34 | 1 根 |

档位越低，趋势项权重越大、阈值越严，信号更少但更晚；档位越高，领先项权重越大、
阈值越松，信号更多更早，假信号也更多。

### 复盘口径

每条预测记录在窗口到期后自动复盘：

- 复盘窗口为当前周期的 5 根K线，下限 10 分钟、上限 14 天；
- 看多需涨幅超过 0.3%，看空需跌幅超过 0.3%，才算判对；
- 观望需涨跌幅绝对值不超过 2%，才算判对；
- 复盘价取窗口到期后第一根K线的收盘价。

不同周期是各自独立的预测，准确率按「币种 + 周期」分开统计。

### 算法版本

`js/signals.js` 的 `ALGORITHM_VERSION` 标记产生信号的算法版本，每条预测记录都会存下
当时的版本号、各因子读数与实际权重。改动影响信号结果或复盘口径的逻辑时，必须升版本号
并在 `ALGORITHM-CHANGELOG.md` 登记改在哪个文件哪个函数、为什么改、预期影响；
只改界面样式、文案、网络超时不需要升版本。按版本分组对比准确率，才能分清准确率的
涨跌是「因子调整起作用了」还是「比较对象变了」。

### 分支与退回约定

`main` 是唯一的长期分支，历史保持**线性**（不留合并提交），推送一律快进。

**推送前先变基到远程**
```bash
git fetch origin
git rebase origin/main   # 只变基本地尚未推送的提交
git push origin main
```

**只 rebase 还没推送的提交。** 已经推上 `origin/main` 的提交一律不 rebase、不强推 ——
强推会改写别人的历史，这恰恰是让「退回旧版本」变得危险的操作。

**退回与撤销**

| 目标 | 命令 |
|------|------|
| 撤销某个已推送的提交 | `git revert <sha>`（新增一条反向提交，原提交完好无损） |
| 临时查看 / 验证旧版本 | `git switch --detach <sha>` |
| 丢掉本地未推送的提交 | `git reset --hard <sha>` |
| 找回误删的提交 | `git reflog` 后 `git branch rescue <sha>` |
| 标记已知可用的版本 | `git tag -a v1.2.0 -m "..."` 然后用 `git push origin v1.2.0` |

因为 `main` 是已推送的分支，撤销一律走 `git revert`（留痕，需要时再 revert 回来），
不用 `reset --hard` 加 `push --force`。
